hubctl · architecture review

One process, four layers, one hardware boundary

The terminal app talks to a driver contract, not to a serial port. The 4CH driver is the only code that knows the wire format. A second device adds a driver module and one registry entry; it does not change the UI or the controller.

Side input hal/discovery.py enumerates candidate ports: Linux sysfs, macOS ioreg, or --port. Each candidate is opened and must answer an identity query. Silence closes it and it is never written to again.

One tick

No worker thread. select(..., 50 ms) bounds the wait; then one device request runs. A full poll is a queue of requests drained across ticks.

01 · INPUT

select, 50 ms

A key runs its action. A toggle performs the whole write path synchronously; a selection only changes local state.

02 · DEVICE

one request

If no key arrived, issue the next request in the poll cycle. A timeout costs at most 0.35 s and is the only source of UI lag.

03 · DRAW

only if changed

The snapshot is the single input to render(). Staleness and link state are fields on it, not computed twice.

0x07 mode→ 0x00 power→ 0x08 data→ 0x03 × N→ 0x04 × N

11 requests for four channels, about 0.3 s, inside the 1 s cycle. Volts and amps are queried one channel at a time because a multi-channel mask is unproven (UNK-015).

The hardware boundary

This is the part the second device plugs into. Values cross the boundary; raw bytes do not. Measurement and D+/D− switching are optional because the vendor family already has models without them.

# hal/base.py - the only surface the controller and the UI know
class DeviceDriver(ABC):
    supports_measurement:  ClassVar[bool] = False
    supports_data_switch: ClassVar[bool] = False

    @classmethod
    def discover(cls) -> Iterable[str]: ...          # candidates, no opens
    @classmethod
    def open(cls, endpoint: str) -> "DeviceDriver": ...  # raises NotThisDevice

    def close(self) -> None: ...
    def identity(self) -> Identity: ...
    def read_status(self) -> Status: ...             # 0x07, one request
    def read_power(self, channels) -> dict[int, bool | None]: ...   # 0x00
    def read_data(self, channels) -> dict[int, bool | None]: ...    # 0x08
    def read_voltage(self, channel: int) -> int | None: ...         # 0x03
    def read_current(self, channel: int) -> int | None: ...         # 0x04
    def read_channels(self, channels) -> dict[int, ChannelReading]: ...  # convenience
    def set_power(self, channels: Sequence[int], on: bool) -> None: ...
    def set_data(self, channels: Sequence[int], on: bool) -> None: ...  # NotSupported


# What the UI consumes
Snapshot(identity, status, channels, link, last_cycle_age_s, last_action, last_error, poll_interval_s)

ChannelReading(power, data, voltage_mv, current_ma)   # None = not known

Errors are part of the contract: NotThisDevice, LinkError, Timeout, NotSupported, Rejected, StateMismatch. Only Rejected changes the mode; only LinkError starts a reconnect; a StateMismatch never does.

What the code must never do

Each rule is enforced in one place, not by discipline across the codebase.

INV-001

No NVM writes

A transport allow-list rejects every setter, reset, reboot, and factory-reset byte before it reaches the port. The UI cannot offer them by accident.

INV-002

No inferred power state

Power comes from 0x00. An off channel reading 202 mV is shown as residual, not as an output.

INV-003

Read both after a switch

Every power write re-reads 0x00 and 0x08. Power-off auto-disconnects D+/D−; power-on reconnect is unproven.

INV-004

No replay after reconnect

Commands are key-driven and never queued, so a new link cannot receive a stale toggle.

INV-005

Identity gate

A reconnect resumes only when product, hardware, firmware, channels, and address match. A different unit stays LOST.

INV-006

Controls only when LIVE

A stale value is dimmed and cannot be acted on. A readback mismatch is reported, not treated as a broken link.

INV-007

One owner

flock(LOCK_EX | LOCK_NB) on the fd. Two instances, or lab_verify, cannot split frames.

INV-008

Terminal restored

Raw-mode enter and leave in a finally, plus SIGTERM/SIGHUP handling. A crash does not leave the shell in raw mode.

Adding the next device

Three steps. If the wire format is the same, step 1 is the only new code.

STEP 1

Driver

devices/<name>/driver.py implements DeviceDriver and sets its capability flags.

STEP 2

Discovery

Return its endpoints from discover() if the transport differs. USB serial reuses the existing enumerator.

STEP 3

Registry + spec

Add the class to DRIVERS. Write docs/hardware/<device>.md before it ships.

Rejected on purpose: dynamic plugin discovery, entry points, a generic instrument abstraction, async I/O, and a background service. Each costs more than the second driver it would serve. A device with no power channels gets its own ABC, not a genericized version of this one.

Open decisions

These change scope, not structure.

What hardware comes after the 4CH?
More SmartUSBHub models reuse this HAL. A different class of instrument (PSU, load, relay) would need a second ABC, which is cheaper than genericizing this one now.
Is a non-interactive CLI wanted?
hubctl status --json would be a second front end over the same controller. It adds a machine-readable contract and exit codes; it does not change the layers.
